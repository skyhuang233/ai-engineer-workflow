# Keep the bootstrap harness outside the product

Until Agent Workflow is complete, development uses the repository-external Bootstrap Development Harness restored from the last coherent product-independent baseline at `7f1bc63`. The harness remains locally available under `.agents/skills` but is not versioned as product source, and neither the Control Plane nor any other product component may depend on it or change behavior to accommodate it. Development-facing agent instructions describe only the Bootstrap Development Harness; the product's Delivery Plan machine contract remains in product code, tests, architecture decisions, and operations documentation. Before Self-Hosting Cutover, the Control Plane must not admit the Agent Workflow source repository as a target and may exercise product behavior only against dedicated test repositories. The existing development Plan and ticket history remain intact, but the self-repository activation marker is removed and its generated Workflow Inbox is closed as inactive history. Existing self-hosting runtime data is retained outside the active runtime path as a local, non-repository archive; later product tests start from isolated state and target only dedicated test repositories. Product changes are retained or reverted according to whether the final product independently requires them, not according to whether work on the harness originally exposed the requirement. Self-Hosting Cutover requires both independent end-to-end production validation and explicit human approval; closed issues, passing tests, or a published release cannot trigger it automatically. This accepts a temporary difference between the way the product is built and the workflow it ultimately provides in order to avoid circular self-hosting and premature runtime complexity.
