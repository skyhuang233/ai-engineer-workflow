# Persist workspaces per Ticket Session

Each Ticket Session owns one isolated, persistent Ticket Workspace that is mounted into its successive run-scoped containers and retained through review until the ticket is Delivered or Cancelled. A normal Candidate Revision leaves the workspace clean with all valid changes committed; an abnormal exit preserves a diagnostic snapshot that the same Ticket Agent may inspect, while a replacement agent starts from the last accepted commit and receives uncommitted residue only as read-only evidence. This uses more disk than fresh checkouts but preserves useful continuity without sharing mutable state across tickets or tying persistence to container lifetime.
