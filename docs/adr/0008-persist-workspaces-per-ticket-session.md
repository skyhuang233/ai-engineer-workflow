# Persist workspaces per Ticket Session

Each Ticket Session owns one isolated, persistent Ticket Workspace that is mounted into its successive run-scoped containers and retained through review until the ticket is Delivered or Cancelled. The Workspace keeps the host's absolute local source checkout as its remote but copies Git objects instead of hard-linking them, so the source and Workspace may reside on different volumes without sharing object files; `TestControllerCreatesIndependentWorkspaceObjectCopies` enforces this boundary through `Controller.Run`. Its repository-local Git configuration fixes `core.autocrlf=false` and `core.eol=lf` at clone and recovery time, keeping the Linux Worker view stable even when the Windows host enables automatic CRLF conversion. A normal Candidate Revision leaves the workspace clean with all valid changes committed; an abnormal exit preserves a diagnostic snapshot that the same Ticket Agent may inspect, while a replacement agent starts from the last accepted commit and receives uncommitted residue only as read-only evidence. This uses more disk than fresh checkouts but preserves useful continuity without sharing mutable state across tickets or tying persistence to container lifetime.
