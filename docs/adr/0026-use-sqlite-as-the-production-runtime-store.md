# Use SQLite as the production runtime store

The single-host, single-Control-Plane topology uses SQLite as its authoritative production runtime store, not as a temporary prototype database. The database lives on a supported local filesystem and uses WAL, foreign-key enforcement, durable synchronous writes, transactional compare-and-swap transitions, uniqueness constraints, and an outbox for idempotent GitHub mutations; schema migrations take verified backups, backup restoration is tested, and integrity checks are operational requirements. Large logs and artifacts remain outside the database with hashes and references recorded inside it. PostgreSQL is not a planned upgrade and becomes relevant only if the accepted topology changes to require multiple concurrent control-plane writers.
