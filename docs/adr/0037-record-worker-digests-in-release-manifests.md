# Record Worker digests and SBOMs in release manifests

The exact GHCR digest cannot exist in the pull request that authorizes a Worker toolchain change because it is produced only after that commit enters `main`. The post-merge publisher therefore attaches exactly two assets to a source-keyed immutable GitHub Worker Release: `worker-release.json` and `worker-sbom.spdx.json`. Manifest schema 6 binds the accepted source commit, Worker version, immutable image digest, pinned Codex, GitHub CLI, Go, and `no-mistakes` versions, the GitHub CLI and Go archive checksums, the distinct `no-mistakes` upstream and fork commits, immutable fork release and release-asset checksum, deterministic Worker build-input identity, the SPDX SBOM checksum, the fail-closed Grype policy, and the Actions run. The upstream commit is required to be the fork commit's merge base, while the release target and binary VCS revision must equal the fork commit. The SBOM is generated from the exact published digest and inventories the packaged `no-mistakes` fork artifact as well as the Worker operating-system and tool dependencies; both pull-request candidates and published images fail on fixable High-or-greater findings. Package managers used only during image construction are removed before scanning rather than excused with VEX.

Release and image tags contain both the declared Worker version and the exact build-input identity, so any Worker source, Dockerfile, pinned publisher-workflow, scanning policy, or consumed toolchain-input change produces a distinct immutable release without a manual version bump. The publisher creates a draft, attaches the manifest and SBOM, publishes only after both assets exist, and then requires GitHub to report the release immutable; repository release immutability is an external production prerequisite. The build-input identity covers the `deploy/worker` Git tree, the pinned publisher-workflow blob, and the Worker toolchain inputs consumed by the build, using one base64-normalized canonical JSON serialization in both the publisher and Doctor. Git remains authoritative for build inputs, the immutable Worker Release Manifest and checksum-bound SBOM are authoritative for the cross-host build output, and SQLite records only which verified release is the current host's Active Worker Image. Doctor may accept a prior owner-accepted manifest only while GitHub reports the release immutable and its pinned inputs and build-input identity still equal those at current `main`; it also downloads the named SPDX 2.3 asset and verifies its checksum before accepting the release. The exact digest must resolve, and the successful `push` run containing the SBOM and vulnerability gates must belong to the active workflow at exactly `.github/workflows/publish-worker.yml`; its source commit must in turn have exactly one non-bot pull request merged by the configured owner. Missing, mutable, mismatched, tampered, or ambiguous provenance fails closed.
