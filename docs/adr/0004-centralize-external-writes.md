# Centralize external writes in trusted controllers

Worker Runs may modify files, create local commits, run quality checks, and produce Candidate Revisions, but they receive no raw GitHub write credentials. The embedded Delivery Controller may monitor read-only CI state and request ticket-scoped branch publication, pull-request updates, and review replies, while the Control Plane's GitHub Write Gateway verifies and executes every mutation. This boundary prevents expired workers from producing zombie writes, limits credential exposure inside code-executing containers, and keeps each external mutation attributable without reimplementing the delivery pipeline.

The Ticket Agent container is otherwise treated as trusted and runs `no-mistakes` directly. Every GitHub mutation requested by that Delivery Controller passes through a narrow GitHub Write Gateway, which derives the allowed repository, branch, and pull request from ticket ownership and rejects an expired lease, an unexpected remote head, direct changes to `main`, or merge operations. This single gateway replaces the earlier idea of a separately sandboxed Delivery Controller and makes Run Lease fencing effective without a broader untrusted-container policy.
