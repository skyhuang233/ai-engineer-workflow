# Keep orchestration outside the no-mistakes fork

The `workflow` codebase owns Delivery Plans, deterministic frontier scheduling, Ticket Sessions, containers, workspaces, Run Leases, budgets, GitHub write fencing, remote CI/review/terminal-state observation, and human-facing projections. A pinned `no-mistakes` fork remains a thin Delivery Controller extension: workflow-routed review feedback enters through the Revision Round intent, validation runs against one exact accepted Candidate, SCM mutations use the lease-fenced Gateway, and the remote CI phase is explicitly marked delegated while the Control Plane distinguishes merged from closed-unmerged. The fork never receives provider credentials and never changes an accepted Candidate through automatic fixes.

Generic changes should be proposed upstream and every upstream update must pass workflow integration tests before adoption. The fork qualification suite must prove strict workflow-mode parsing, automatic gate initialization, immutable Candidate validation, absence of direct provider mutation, exact Gateway fencing fields, and explicit CI delegation. This prevents a global agent platform from becoming an unmaintainable fork of a per-repository delivery tool.
