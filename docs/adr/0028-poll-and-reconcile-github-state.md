# Poll and reconcile GitHub state

The local Control Plane discovers reviews, comments, CI results, and pull-request changes through durable incremental polling of only relevant active plan objects, with event-identity deduplication, adaptive intervals, rate-limit awareness, retry backoff, and persisted cursors. A fenced per-repository SQLite poll lease atomically enforces each cursor's next-attempt boundary before credential access or GitHub I/O and conditions every shared poll-cursor transition on the current lease token. Cold-start recovery records the immutable Plan version whose rejected Workflow Inbox projection established eligibility and can be claimed only while that same current version remains projecting; absent, replaced, completed, and terminated Plans cannot acquire that recovery path. Credential rejection durably pauses Gateway writes while resetting the poll retry budget, so credential repair resumes polling without terminalizing the Plan. Periodic full reconciliation repairs ordering-boundary or cursor mistakes and restores state after downtime. A future webhook may wake the poller sooner but can never become the sole correctness source, avoiding public ingress infrastructure while making delivery robust to duplicate, delayed, and missed notifications.
